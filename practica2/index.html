PRÁCTICA N2 - GIT, GITHUB Y HTML

  1. ¿Qué es Git y cuál es su función principal dentro de un proyecto de desarrollo?

    2. Respuesta: Git es un sistema de control de versiones. Su función principal es
    (registrar el historial de cambios del código y permitir que varios desarrolladores
    trabajen en equipo de forma ordenada), evitando que se pierda información o
    se sobrescriba el trabajo de otros.

  2. ¿Cuál es la diferencia entre Git y GitHub y qué función cumple cada uno?

    3. Respuesta: La diferencia principal es que Git es el software que instalas en tu computadora
    para controlar las versiones de tu código, mientras que GitHub es una plataforma en la nube
    para almacenar, compartir y colaborar en esos proyectos.

  3. ¿Qué pasos se deben seguir en Git para guardar los cambios realizados
    en un proyecto y crear un commit?

    4. Respuesta: Para guardar los cambios y crear un commit en Git,debes seguir estos 3 pasos básicos:

    1. Verifica el estado → git status
    2. Preparar los cambios → git add .
    3. Crear el commit → git commit -m "Descripción clara de los cambios realizados"

  4. ¿Qué comandos se utilizan para conectar un repositorio local con un repositorio
    de GitHub y posteriormente subir los cambios? Explique brevemente la función
    de cada uno.

    5.

    Respuesta : Los comandos principales para conectar un repositorio local con GitHub son:

    • git remote add origin URL → conecta el repositorio local con GitHub.
    • git branch -M main → establece la rama principal como main.
    • git push -u origin main → sube los cambios a GitHub.

  5. ¿Qué es una rama (branch) en Git y en qué situaciones puede ser útil trabajar
    con una rama diferente a main?

    6.

    Respuesta :Una rama es una versión independiente del proyecto. Es útil para desarrollar nuevas
    funciones o hacer cambios sin modificar directamente main.

  6. Explique el proceso para crear una nueva rama, realizar cambios en ella y
    posteriormente subir esa rama a un repositorio de GitHub.

    7.  Respuesta:
    1. git branch nueva-rama → crea la rama.
    2. git checkout nueva-rama → cambia a la rama.
    3. Se realizan los cambios.
    4. git add . y git commit -m "cambios" → guardan los cambios.
    5. git push -u origin nueva-rama → sube la rama a GitHub.

  7. ¿Qué es un conflicto en Git y qué pasos se deben seguir para resolverlo antes de
    combinar los cambios de una rama con main?

    8.

    Respuesta : Un conflicto ocurre cuando dos ramas modifican la misma parte de un archivo
    de forma diferente. Se debe identificar el conflicto, corregirlo manualmente, ejecutar git add . ,
    crear un commit y luego combinar la rama con main.
